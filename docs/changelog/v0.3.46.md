# v0.3.46 — /projects/eum hero monitor 와이드 뷰포트 height-driven 복귀

## 작업한 내역

- `2026-05-20` `src/app/projects/eum/_style/projects.eum.scss` — `.monitor-frame`에서 v0.3.35의 width-driven 설정(`width: 100%; max-width: 100%; height: auto`)을 제거하고, 공통 rule(`height: 100%; width: auto`) 기반의 height-driven으로 복귀. wrapper의 1200 폭 캡을 우회하도록 `max-width: min(calc(100vw - 96px), 1512px)`(viewport-anchored) + `aspect-ratio: 3024 / 1964` 적용. screen 내부의 `aspect-ratio`, `max-width: 1512px`, `height: auto`를 제거하고 `width: 100%; height: 100%`로 단순화.

## 배경

1920×1080 와이드 뷰포트에서 monitor 영상(02번)이 wrapper height 876px 중 779px만 사용해 위·아래에 빈 공간이 컸음. 원인은 v0.3.35에서 monitor를 width-driven으로 전환하면서 wrapper의 `max-width: 1200px` 캡이 binding constraint가 되어, monitor aspect(3024/1964 ≈ 1.54) > wrapper aspect(1200/876 ≈ 1.37)인 와이드+짧은 뷰포트에서 세로 공간이 남게 된 것.

수정안은 사용자 지시에 따라 wrapper 폭 캡은 1200 그대로 유지하고 monitor만 viewport-anchored max-width로 캡을 우회. `left: 50%`는 wrapper 중심이지만 wrapper가 viewport 중앙에 위치하므로 결과적으로 viewport 중앙 정렬됨. phone(`right: 0`)은 wrapper 1200 우측 flush 그대로 유지되어 monitor 우측 끝과 약간 어긋날 수 있음(트레이드오프 수용).

### 뷰포트별 거동
- 1920×1080: wrapper 1200×876, monitor 1349×876 (height-bound, max-width 1512 비바인딩)
- 1440×900: wrapper 1200×792, monitor 1219×792 (height-bound)
- 800×600 (좁고 짧음): wrapper 800×396, monitor 610×396 (height-bound, max-width 704 비바인딩)
- 800×1200 (좁고 길음): wrapper 800×996, monitor 704×457 (width-bound, max-width 704 발동)

### 사이드 이펙트
- `box-sizing: border-box` + outer 박스 `aspect-ratio`로 padding 12px 만큼 inner(screen) aspect가 ~1% 미스매치 — video의 `object-fit: cover`가 사실상 보이지 않는 crop으로 흡수
- 1512px max-width는 screen이 아닌 frame outer 기준이라 screen은 ~1488까지 — 레티나 가드 라인(1512 = source 3024 ÷ 2)에 사실상 동일
