# v0.3.23 — /projects/eum 히어로를 video → image slideshow로 전환

## 작업한 내역

- `2026-05-18` `src/app/projects/eum/page.js` — `<video>` element + `currentTime` 점프 방식(v0.3.22) 완전 폐기. `HERO_ITEMS`에 영상별 webp `frames[]` 배열을 두고 `<img>`로 표시. 모든 프레임(영상01·02: 5장, 영상03: 4장 = 총 14장)을 DOM에 두고 opacity 토글로 전환 → 페이지 진입 시 캐시 적재 후 깜빡임 없음. `setInterval`이 frameIdx를 진행하다 마지막 도달 시 `setActive`로 다음 영상으로 cycle. v0.3.21의 hi/lo + DPR 분기 useHi 제거(img는 브라우저가 image-quality 알고리즘으로 정확히 다운스케일하므로 단일 고화질 webp 한 벌이면 모든 DPR에서 깔끔).
- `2026-05-18` `eum/posters/hero/final_prototype_0{1,2,3}_f{00..04}.webp` (R2) — ffmpeg로 hi mp4에서 0%, 25%, 50%, 75%, ~99% 지점 PNG 추출 → cwebp `-q 92` 변환하여 신규 업로드(총 14장, 약 1.5MB). 영상 원본 6개 mp4(hi×3 + lo×3)는 그대로 유지(롤백·재인코딩 작업에 재활용 가능).

## 배경

v0.3.22의 step-jump(video element + currentTime 점프)는 자동재생을 멈춰 시간적 알리아싱을 제거했으나, **정지된 video 프레임 자체에 H.264 P/B 프레임의 양자화 오차가 그대로 노출되어 여전히 화질이 떨어진다는 보고**. 자동재생 시에는 motion blur가 가렸지만 정지하면 압축 아티팩트가 가감 없이 보임. keyscreen #01과 hero #01의 소스 mp4는 사실상 동일한데도 keyscreen이 더 깨끗했던 이유는 콘텐츠 특성(정적 UI는 코덱이 효율적)이라 hero에는 그 효과가 안 통했음.

근본 해결: video 코덱 자체를 우회. 각 영상에서 키 프레임을 webp(`-q 92`)로 추출해 `<img>`로 표시. webp 이미지는 (a) P/B 의존성 없는 단일 정지 이미지 (b) 브라우저가 image-quality 다운스케일 알고리즘 적용 (c) 정확한 픽셀 렌더링 — 모든 DPR 환경에서 keyscreen 수준 선명도 보장.

부수 효과:
- 영상 6개(약 6.5MB) → webp 14개(약 1.5MB)로 페이지 총 자산 ↓
- video element와 디코더 자체가 사라져 컴퓨터 부담 v0.3.22보다 더 낮음
- DPR 분기 로직 불필요(img는 자동 처리)
