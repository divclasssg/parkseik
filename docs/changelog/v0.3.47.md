# v0.3.47 — /projects/eum hero monitor aspect-ratio 깨짐 방지 (min() 단일 식)

## 작업한 내역

- `2026-05-20` `src/app/projects/eum/_style/projects.eum.scss` — `.monitor-frame`의 width를 `min(calc((100svh - 204px) * 3024 / 1964), calc(100vw - 96px), 1512px)` 단일 식으로 명시. v0.3.46의 `max-width: min(...)` + 공통 `height: 100%` + `aspect-ratio` 조합을 height: auto + 명시적 width로 전환.
- `2026-05-20` `src/app/about/_style/about.style.scss` — `p`에서 `color: #66666f` 제거(기본 본문 컬러로 회귀).

## 배경

v0.3.46이 2560 모니터(레티나) 환경에서 monitor 베젤의 가로세로 비율이 깨지는 회귀를 만듦. 원인은 다음 조합:

- 공통 rule: `height: 100%`(wrapper 높이 결정)
- v0.3.46 override: `max-width: min(calc(100vw - 96px), 1512px)`, `aspect-ratio: 3024 / 1964`

CSS-sizing-4 스펙은 max-width가 binding되면 aspect-ratio로 height를 재계산해야 한다고 명시하지만, 실제 브라우저(특히 height가 이미 100%로 explicit하게 정해진 경우)는 explicit dimension을 우선시해 aspect-ratio를 무시하는 케이스가 존재. 2560 viewport에서 wrapper 1200×1236 + max-width 1512 cap → width 1512, height는 100%(1236) 그대로 유지되어 1512×1236 (aspect 1.22)로 가로가 짧고 세로가 긴 변형 발생.

## 해결

aspect 깨짐 가능성을 없애기 위해 width를 단일 `min()` 식으로 모든 제약(height-driven 한계 / viewport 가로 한계 / 1512 retina cap)을 명시. height는 `auto`로 두고 `aspect-ratio`가 항상 정확히 도출하도록 변경.

### 뷰포트별 거동
- 1920×1080: width = min(1349, 1824, 1512) = 1349 → height 876 (이전과 동일, wrapper 높이 100% 채움)
- 2560×1440: width = min(1903, 2464, 1512) = 1512 → height 981 (1512×981, aspect 정확)
- 2560×1600: width = min(2149, 2464, 1512) = 1512 → height 981 (1512×981, 와이드+큰 뷰포트도 1512 retina cap 유지)
- 1440×900: width = min(1072, 1344, 1512) = 1072 → height 696 (전 영역 사용)
- 1280×720: width = min(794, 1184, 1512) = 794 → height 516
- 800×600: width = min(610, 704, 1512) = 610 → height 396
- 800×1200 (좁고 김): width = min(1534, 704, 1512) = 704 → height 457

### 100svh 사용 이유
모바일 동적 UI 바 변화에 안정적. hero 자체가 `calc(100svh - 108px)` 기준이므로 monitor도 동일 단위로 통일.
