# v0.3.21 — /projects/eum 히어로 영상 외장 1080p(DPR=1) 모니터 깨짐 해결

## 작업한 내역

- `2026-05-18` `src/app/projects/eum/page.js` — `VIDEOS` 배열에 `srcLo` 추가, `useHi` state + `useEffect`로 `window.devicePixelRatio >= 1.5` 감지, `<video>`의 `src`를 DPR에 따라 hi/lo로 분기. 첫 paint(SSR+초기 CSR)에서는 src 미설정, 마운트 후 사용자 디바이스에 맞는 한 벌만 다운로드. play() 트리거 useEffect의 deps에 `useHi` 추가하여 src 결정 시점에 active 영상이 재생되도록 보정.
- `2026-05-18` `eum/videos/hero/final_prototype_0{1,2,3}_lo.mp4` (R2) — hi 영상을 절반 해상도로 다운스케일(`scale=W/2:H/2:flags=lanczos`) + 60fps + CRF 18로 인코딩하여 신규 업로드. 결과: 01 660×1434 (1.4MB), 02 1512×982 (1.5MB), 03 388×840 (546KB). DPR=1에서 1:1 매핑.

## 배경

v0.3.20에서 retina 디스플레이 깨짐은 해결됐으나, 외장 1080p(DPR=1) 모니터에서는 여전히 알리아싱·모이레가 심각하다는 보고. 진단 결과 `<video>`의 브라우저 다운스케일 알고리즘이 `<img srcset>`만큼 정교하지 않아 2x 다운스케일에서 픽셀 노이즈가 두드러짐. 베이크된 10x 영상은 빠른 모션 + UI 텍스트가 많아 특히 심함.

해결: hi(소스÷2가 1:1, retina용) + lo(소스÷4가 1:1, 일반 모니터용) 두 벌을 R2에 두고 JS가 DPR을 보고 src 분기. retina는 hi 그대로, DPR=1에서는 lo로 1:1 매핑되어 다운스케일 자체가 사라짐. 사용자는 자신의 디바이스에 맞는 한 벌만 다운로드.

CSS([[feedback_retina_media_cap]] 캡 규칙) 및 R2의 hi 객체는 v0.3.20 그대로 유지.
