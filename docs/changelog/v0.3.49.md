## 배경

v0.3.48에서 R2 PNG 3장을 임베드하고 memory `feedback_retina_media_cap` 규칙(소스÷2 cap)에 따라 `picture { max-width: 525px }` 적용. 사용자(DPR=1 1080p 1920 뷰포트) 환경에서 카드 이미지 본문 글자가 "안 보이고 흐릿한" 상태가 됨.

원인 분석:

- 표시 폭 525 CSS px × DPR=1 = 525 device px
- 소스 PNG 폭 1050~1178 → 약 50% 다운샘플
- 소스 본문 글자가 14~18px 추정 → 다운샘플 후 7~9px → 가독성 한계 이하

retina cap 525는 DPR=2 retina 환경 보호를 위한 강제 규칙. DPR=1 단일 환경에서는 과보호여서 정보 손실이 큼.

## 결과 표시 폭 (1920 뷰포트, box-sizing: border-box)

전역 `.section-content max-width: 1024` 는 그대로 유지. `.card-bleed` 최대 1096 → 부모 1024로 캡됨.

| 항목 | 계산 | CSS px |
| --- | --- | --- |
| section-content max | (1024) | 1024 |
| card-bleed inner (odd, border 2 + padding-left 36) | 1024 − 2 − 36 | 986 |
| card-bleed inner (even, border 2 + padding-right 48) | 1024 − 2 − 48 | 974 |
| card-media (odd) | 986 − 300 − 64 | 622 |
| card-media (even) | 974 − 300 − 64 | 610 |

DPR=1: 610~622 device ← 1050~1178 소스 → 53~59% 다운샘플 → 본문 글자 ~8.4~10.8px 회복(이전 525 폭 / 7~9px 대비 ~20% 향상).
DPR=2 (retina): 1220~1244 device > 모든 소스 → 약 4~18% 업스케일 흐림 (의도된 트레이드오프, 후속 2x 자산으로 해소 예정).

## 트레이드오프 명시

memory `feedback_retina_media_cap` 규칙(소스÷2 cap)을 의도적으로 위반한 상태. 주 타깃 환경(DPR=1)에서의 가독성 회복을 우선시한 판단. retina에서는 4~18%의 가벼운 업스케일 흐림이 발생하지만, 다운샘플 50%로 인한 정보 손실보다는 정보 보존 관점에서 우위. 후속 2x R2 자산이 업로드되면 srcSet `<2x> 2x` 슬롯에 그대로 꽂혀 retina 흐림도 자동 해소되도록 마크업 골조 확보.

## 함께 진행한 시각 보강

`.card-bleed` 에 `border: 1px solid #e5e5ea` 추가 — 흰색 배경 위에 옅은 회색 외곽선으로 카드 경계 명확화. card-bleed가 차지하는 영역과 그 안의 본문/이미지 영역 구분이 또렷해짐.
