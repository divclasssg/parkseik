- `2026-05-17` `sectionkeyscreens.js` + `projects.eum.scss` 갱신 — 02 segment(wide #02) 활성 시 sticky에 `swap` 클래스 토글로 텍스트↔영상 좌우 위치 반전. 초기엔 `flex-direction: row-reverse`로 구현했으나 flex-direction은 transition 불가해 위치가 즉시 점프하는 문제 발견. callout-area와 asset-area 각각에 `transform: translateX` + `transition: transform 0.5s ease`로 변경해 부드럽게 슬라이드 swap되도록 수정. `bg-subtle` 톤 전환(0.4s)과 거의 동기. 모바일 mq에서는 두 영역 모두 `transform: none !important`로 swap 무력화.
- `2026-05-17` keyscreen 구조 재설계 (`finalkeyscreens.js` + `sectionkeyscreens.js` + `projects.eum.scss`) — 위 동적 swap 방식도 "#02가 올라온 뒤 swap이 일어나 갑작스럽다"는 피드백 발생. 데이터 기반 정적 레이아웃으로 재설계: 기존 `callout-area`(텍스트 한 자리 fade) + `asset-area`(영상 트랙) 2-컬럼 구조 폐기, 단일 `keyscreen-track` 안에 row 3개(각 row = [callout, asset] 페어). 데이터 `reverse` 필드(#02만 true)로 `keyscreen-row.reverse { flex-direction: row-reverse }` 적용 → #02가 viewport에 진입하는 시점부터 이미 영상이 좌측·텍스트가 우측에 정적으로 배치. swap 토글 로직(SWAP_INDEX, swapActiveRef, `.swap` 규칙, transform translateX, transition)은 모두 제거. portfolio 원본 대비 trade-off: callout이 row와 함께 트랙 슬라이드(원본은 sticky 한 자리 fade)되지만 callout 자체 transform/opacity micro-animation은 row 내부에서 그대로 유지되어 fade 의도는 살아남.
- `2026-05-17` 스크럽 종료 후 빈 공간 제거 (`sectionkeyscreens.js` + `projects.eum.scss`) — 마지막 #03 스크럽 끝(HOLD 끝, local 0.75) 이후 EXIT 구간(0.75~1.0) 동안 트랙이 `-100%` translateY로 슬라이드되며 viewport에 빈 화면이 길게 남는 문제. KeyScreens가 페이지 마지막 섹션이라 portfolio 원본의 다음 섹션 연결 매커니즘이 작동 안 함. 해결: JS 트랙 슬라이드/callout fade-out 로직에서 마지막 segment(`activeIndex === ITEM_COUNT - 1`) 예외 처리 — EXIT 슬라이드와 fade-out 모두 건너뜀(HOLD 상태 유지). SCSS `keyscreen-scroll-container` 높이 4800vh → 4400vh로 마지막 EXIT 분량(약 360vh, #03 duration 비례 25%) 차감. 결과: #03 row가 viewport 정중앙에 도달한 채 sticky가 자연스럽게 해제되며 페이지 끝과 매끄럽게 연결.
