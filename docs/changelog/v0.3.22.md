# v0.3.22 — /projects/eum 히어로 영상을 step-jump 모드로 전환

## 작업한 내역

- `2026-05-18` `src/app/projects/eum/page.js` — 자동재생(`play()`/`pause()`/`ended` 리스너) 제거하고 **step-jump 모드**로 교체. `VIDEOS` 각 항목에 `keyFrameCount`·`perFrameMs` 메타 추가(01·02: 5프레임/1200ms, 03: 4프레임/1000ms). 단일 `useEffect`가 `loadedmetadata` 대기 후 `setInterval`로 일정 간격에 `v.currentTime = (idx/(N-1)) * duration` 점프하고, 마지막 키 프레임 도달 시 `setActive`로 다음 영상으로 cycle.

## 배경

v0.3.20(소스 재인코딩) + v0.3.21(hi/lo + DPR 분기) 이후에도 외장 1080p(DPR=1) 모니터에서 hero 영상이 깨져 보임. 반면 같은 페이지의 keyscreen 섹션 영상은 같은 환경에서 선명.

진단: keyscreen의 `ScrubVideo`는 자동재생을 하지 않고 스크롤 진행률에 따라 `v.currentTime`만 점프해 사실상 정지 프레임을 표시. hero는 60fps 자동재생이라 매 16.7ms 디코드 → 매 프레임의 양자화 오차·서브픽셀 정렬 차이가 누적되며 DPR=1에서 **시간적 알리아싱(temporal aliasing)**으로 두드러짐. 정지 프레임의 압축 아티팩트는 사람 눈이 인지하기 어렵지만, 매 프레임 변동하는 알리아싱은 "지글거림"으로 인지됨.

해결: hero도 keyscreen 패턴을 차용하여 _자체 타이머로 키 프레임만 점프_. 자동재생 제거로 GPU 디코더·컴포지터가 idle → 컴퓨터 부담 대폭 감소(자동재생 시 10~20% → step-jump 시 1~2% 수준 추정). 베이크된 10x 연속 motion은 사라지지만 각 키 프레임이 keyscreen 수준의 정적 선명도로 표시됨.

R2 영상(v0.3.20 hi + v0.3.21 lo, 총 6개)과 DPR 분기 코드는 그대로 유지 — step-jump는 hi/lo 어느 쪽이든 동일하게 적용.
