## 배경

v0.3.50에서 portfolio의 `define-methodology-scroll-container`를 이식한 직후, 사용자(DPR=1 1080p) 환경에서 methodology 섹션 callout 텍스트가 흐릿하게 보이는 회귀가 관찰됨.

### 원인 분석

`.define-methodology-callout-area`의 `mask-image: linear-gradient(transparent → black 18% → black 82% → transparent)`가 부모 레이어 전체를 비트맵 raster 처리하도록 강제. 자식인 `.define-methodology-callout`은 `will-change: transform, opacity` + `transform: translate3d(0, 120px, 0)` 조합으로 GPU 컴포지팅 레이어가 된 상태. 두 효과가 결합되며 텍스트의 **subpixel antialiasing(LCD color fringing)** 이 **grayscale antialiasing** 으로 강등됨.

DPR=2 retina에서는 device pixel 밀도가 충분히 높아 raster화돼도 차이가 잘 안 보이지만, DPR=1 1080p에서는 subpixel AA가 LCD 색상 fringing으로 텍스트를 한층 선명하게 만드는 역할이 큰데, 이게 사라지면서 텍스트가 살짝 부드럽고(=흐릿하게) 보임. portfolio는 retina 환경에서 개발/QA되었기 때문에 발견되지 않았던 회귀.

### 해결 방향

mask를 제거하고 동등한 fade 시각효과를 흰색 그라데이션 pseudo overlay로 대체. callout 텍스트는 mask 컨텍스트 밖에서 렌더되어 subpixel AA가 복원. 부수적으로 `will-change`도 제거해 GPU layer 강제 promotion에 의한 raster 부수효과 추가 차단.

## 시각 효과 비교

| 항목 | 기존 mask | 신규 pseudo overlay |
| --- | --- | --- |
| 위/아래 18% fade | mask alpha 0 (텍스트가 진짜 사라짐) | 흰색 그라데이션이 텍스트 위 덮음 (흰 배경에 묻혀 사라지는 효과) |
| 텍스트 렌더 | grayscale AA (흐림) | subpixel AA (crisp) |
| 배경 종속성 | 무관 | 페이지 배경이 흰색이라는 전제 — define 섹션 배경 변경 시 overlay 색 같이 조정 필요 |
| 뒤 dim 이미지 | mask가 잘라 점진적 fade | overlay 흰색이 위에 덮어 동일하게 가림 |

흰 배경 위에서 시각적으로 거의 동일.

## 트레일링 여백 제거 배경

container 높이 1600vh = scrub 영역 1500vh + sticky 자연 해제 영역 100vh 구조. 기존 로직은 마지막 아이템도 `local >= HOLD_END` (0.82) 부터 fade-out 시작 → `totalProgress=1` (scrollTop=1500vh) 시점에 op=0. 이후 트레일링 100vh sticky 해제 zone에서는 콘텐츠가 op=0 invisible 상태로 sticky 엘리먼트가 위로 빠져나가는 동안 사용자 시야에 빈 공간만 보임 → "여백이 너무 많다" 회귀.

마지막 아이템만 HOLD 유지하도록 변경하면, sticky 해제 zone 동안에도 콘텐츠가 화면에 남아 자연스럽게 위로 이동·다음 섹션이 viewport 하단에서 등장. sticky 해제 메커니즘 자체는 그대로 두고 시각적 끝맺음만 보강.

## 후속 (별도)

- pseudo overlay 색상을 CSS 변수화하여 dark mode 또는 surface tint 대응.
- 흐림이 1차 변경으로 미해결 시 `translate3d(0, 120px, 0)` → `translateY(120px)` (2D transform)로 교체해 GPU layer 강제 해제 시도.
- 1·2·4 카드 headline에도 줄바꿈 의도가 있다면 `_data/defineMethodology.js` 의 해당 문자열에 `\n` 추가만으로 적용 가능 (CSS는 이미 준비됨).
