## 배경

v0.3.30에서 lo 분기를 제거하고 hi 단일 서빙으로 회귀했음에도 외장 1080p · DPR=1 모니터에서 글씨 깨짐 지속. 2차 진단:

1. **R2 hi 3종 비트레이트가 너무 낮음** (실측 ffprobe):
    - `final_prototype_01.mp4` 1320×2868 60fps **2.7 Mbps** (bpp 0.012)
    - `final_prototype_02.mp4` 3024×1964 60fps **3.1 Mbps** (bpp 0.0087)
    - `final_prototype_03.mp4` 774×1678 60fps **2.7 Mbps** (bpp 0.035)
    - UI 영상 권장 0.05–0.15 bpp의 1/4~1/15 → 인코딩 단계에서 글자 엣지가 모기 노이즈/블록 아티팩트로 손상. 마스터(`portfolio/eum/videos/hero/final_prototype_01.mp4`도 3.2 Mbps)가 천장이라 CRF 18 재인코딩으로는 회복 불가.
2. **표시 CSS 크기가 작음**: 1080p 뷰포트에서 flex column 분할(section-content 180 + 32 margin + 160 padding = 372 px 차감) 결과 video-wrapper ≈ 600 px → phone-frame 폭 294 CSS px, 안쪽 비디오 264 CSS px. UI body 텍스트가 화면상 약 4–6 px → 가독성 임계 아래.

비트레이트 회복(A안)은 마스터 천장 때문에 별도 작업으로 분리. 본 버전은 **레이아웃 재구성으로 표시 크기를 키워(B안) 가독 임계 회복**.

새 레이아웃: hero가 flex column이 아니라 `position: relative` 컨테이너, `.video-wrapper`가 hero 전체를 absolute fill, `.section-content`(브랜드 콜아웃)는 absolute 오버레이로 hero 하단에 배치. 1080p 기준 wrapper 높이 600 → ~972 px, phone-frame 폭 294 → ~445 CSS px(≈1.5×), 안쪽 비디오 264 → ~400 CSS px. 모바일(<640px)도 wrapper가 120 → ~500 px로 회복되어 별도 미디어쿼리 불필요.

콜아웃이 phone-frame 하단부와 겹치는 건 디바이스 mockup 위 caption 패턴으로 수용. 가독성 우려시 후속에서 `backdrop-filter: blur(8px)` 또는 phone-frame `height: 90%` 로 조정.
